json_body

json_body(response: HttpResponse) -> Json

defon anyraises(HttpError)raises(JsonError)

The body read as JSON. Fallible twice, and the two failures stay apart.

`raises(JsonError)` is inferred from `json_parse` and `raises(HttpError)` from `require_ok`, so the row of this function names both and a handler catches the one it can say (`docs/47` §47.4).

parsed

parsed(response: HttpResponse) -> Result[Result[Json, JsonError], HttpError]

defon anyno effects

Both of `json_body`'s failures, caught one handler each.

The nesting is the point rather than a nuisance: a `try:` catches the failure its type names and lets every other one travel (`docs/47` §47.4), so "the peer said 503" and "the peer said something that is not JSON" cannot be confused for one another by a caller that wanted to tell them apart. A caller that does not want to tell them apart writes one `try:` further out.

`POST` with a body, and the length the peer needs to read it.

`content-length` is set here rather than by the client because a request is data: two runs that build the same request send the same bytes, and a header added underneath would be a difference the program could not see.

request

request(method: Str, path: Str) -> HttpRequest

defon anyno effects

A request with nothing in it but a method and a path.

Port 80 because this is HTTP; `on_port` changes it. The path is origin-form and is sent as written — `"/v1/todos?limit=10"` is one string, because only the caller knows which part of it was data and therefore which part needed encoding.

require_ok

require_ok(response: HttpResponse) -> Str

defon anyraises(HttpError)

The body of a 2xx reply, or a raise carrying the status and the body.

The primitive raises only when *nothing arrived*: a 500 is a reply, and a client that threw it away would have thrown away the sentence saying why. A caller that would rather not decide gets this — and note that it raises the same `HttpError` the primitive does, so one `try:` catches both a peer that was down and a peer that said no.

defon anyno effects

Set a header, under a lower-cased name.

Lower-cased both here and in `header`, so that a program never has two spellings of one header: HTTP header names are case-insensitive and a `map[Str, Str]` is not.

with_secret_header

with_secret_header(req: HttpRequest, name: Str, value: secret[Str]) -> HttpRequest

defon anyno effects

Set a header whose value is a secret — the only way a credential reaches a peer.

§3.5 gives a program no way to read a `secret[Str]`: there is no `reveal` for one, which is exactly the claim that makes a secret unable to reach a browser. So `"Bearer " + key` is not a thing anybody can write, and an authenticated request would be inexpressible if this took a `Str`. It takes the secret itself, the runtime merges it into the headers at the edge, and the request that results is not Sendable — so the type system says, without anyone asserting it, that this request cannot be built on a client or handed to one.
