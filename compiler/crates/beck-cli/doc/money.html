Money

model Money

An exact amount in one currency, held as a whole number of minor units.

`Money(units=250, currency="GBP")` is £2.50. The scale is the currency's, not the value's, so two amounts in the same currency are always directly comparable — which is the property that makes a fold over a ledger a sum rather than a negotiation.

`[0, 1, …, n - 1]`, written here rather than asked of the prelude.

A range is the one piece of this file that is *not* about money, and it is written in Beck for the same reason the rest is: it can be. It is a tail-recursive accumulation, which costs no host stack at all (`docs/31`), so `range_to(250_000)` is a list and not a crash.

render

render(m: Money) -> Str

defon anyno effects

`250` in `"GBP"` renders as `"2.50"`. Two minor digits, which is right for most of the world's currencies and wrong for JPY and KWD — stated because a library that is quietly wrong about a currency is worse than one that says which.

same_currency

same_currency(a: Money, b: Money) -> Str

defon anyraises(MoneyError)

The two amounts' shared currency, or a raise.

Every operation that combines two amounts goes through this, so "you cannot add pounds to euros" is one line rather than a rule four functions each remember. `raises(MoneyError)` is inferred from it and travels outwards by itself — which is `docs/45`'s property doing the work a library is exactly where you want it doing.

split

split(m: Money, parts: Int) -> list[Money]

defon anyraises(MoneyError)

Split an amount into `parts` as evenly as an integer allows, largest remainder first.

The property that matters is that the parts sum back to the original: £10 in three is £3.34 + £3.33 + £3.33, never three lots of £3.33 with a penny unaccounted for. A library that rounds each part independently loses money, and it loses it silently, which is why this is here rather than left to a caller with a division.

times

times(m: Money, n: Int) -> Money

defon anyno effects

An amount times a plain number: `price * quantity`.

Money times money is not money — £2 × £3 is not an amount of anything — so there is no such operation here at all, which is the other half of why `Num` is the wrong shape for this type.
