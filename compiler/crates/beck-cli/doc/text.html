lines

lines(text: Str) -> list[Str]

defon anyno effects

Split on newlines, dropping a single trailing one.

A file that ends in a newline has the same lines as one that does not, which is what every tool that reads a file means by "lines" and what `str_split` alone does not give you. An empty string therefore has no lines rather than one empty one.

no_pairs

no_pairs() -> Map[Str, Str]

defon anyno effects

An empty `Map[Str, Str]`, because `{}` on its own is not one yet.

A record literal is checked against an expectation, and the second argument of `list_fold` has none to offer: its type is only decided once the *third* argument has been read. Writing the empty map behind a signature is how a program says which map it means, and it is worth one definition rather than a change to the order the checker reads arguments in.

parse_pairs

parse_pairs(text: Str, between: Str, within: Str) -> Map[Str, Str]

defon anyno effects

`"a,b" → {"a": "", "b": ""}` is not what anybody means, so this takes pairs.

`parse_pairs("a=1;b=2", ";", "=")` is `{"a": "1", "b": "2"}`. A pair with no separator is skipped rather than raising: this is a *tolerant* reader for things like a cookie header, and a strict one would be a different function with a `raises` in its row.

Shorten to `width`, ending in `…` if anything was dropped.

The ellipsis counts towards the width, because a "truncate to 10" that returns 11 characters is the bug this function exists to not have.

words

words(text: Str) -> list[Str]

defon anyno effects

Split on whitespace, dropping the empty runs.

`str_split(s, " ")` gives `["a", "", "b"]` for `"a b"`, which is correct for a split and wrong for words — so the difference is one `filter_list`, and having to write it is the point.
